## What you must run yourself, with an API key

Nothing below has been run yet. Each needs a **private** repository made from this template with the
`ANTHROPIC_API_KEY` secret set. Before starting, mark this repository as a template:
Settings > General > Template repository.

### Stage 1 on each example

For each of `apps-script-feedback` and `python-support-triage`:

1. Leave `input/` empty. Actions > **1. Scan my project** > Run workflow, choosing the example.
2. Check the run succeeds and an issue labelled `portfolio-demo` opens.
3. Check the issue has:
   - the permission reminder at the top;
   - exactly 5 summary lines in plain English;
   - a table grouped PERSONAL, PROPRIETARY, SECRET, SAFE, UNSURE with KEEP/FAKE/REMOVE and a reason per row;
   - questions about steps outside the code (e.g. "Wren reads every note" / "Hattie or Marcus checks each draft"), what to feature, and what not to state about production;
   - no full names, emails, keys, sheet IDs or internal URLs (all masked or described);
   - the hidden `<!-- pdk:folder=... -->` marker (view the issue body source).
4. Check the cost comment: agent tokens and cost are filled in, or it says "not reported" and where to look.
   If "not reported", the action's `execution_file` format differs from what `scripts/usage_report.py` expects.

### Stage 2 on each example

1. Reply in the issue, e.g. for apps-script-feedback:
   *"Keep the trait names (Anchor, Kindle, Lattice, Horizon). Fake the role descriptions and all people. Remove the key and links. Wren reviews every note by hand before it is emailed. Feature the writing rules. Don't state how many staff used it."*
   For python-support-triage:
   *"Fake all customers and orders. Keep the topic list. The refund policy is proprietary: summarise it, don't quote it. A person checks every draft. Don't mention the office PC."*
2. Comment `/build` on its own line.
3. Check: a "Building your demo" comment appears; the run succeeds; the final comment links to
   `demo.zip` and `SANITISATION.md`, shows "Leak scan: PASSED", 0 of 10 canaries, self-test "caught",
   and a cost table.
4. Download `demo.zip`. Check it holds only `index.html`, `data.json`, `diagram.svg`, `README.md`,
   `SANITISATION.md` (no `.git`, no hidden files).
5. Open `index.html` on a phone or at 380px wide: four sections, the diagram readable, the explorer
   switches between cases, every output shows a provenance label, "Generated by ..." labels name a real model.
6. Check the diagram shows only confirmed steps (the manual review appears; nothing invented).
7. Check SANITISATION.md describes what was found without repeating it, and the scan table is filled in.
8. Search the unzipped files for any name, email, order number or phrase from `examples/*/before/`.

### Failure paths

- Comment `/build` from an account without write access: expect a refusal comment and no build.
- Comment "please /build this" (not on its own line): expect no build.
- Make the repository public and run Stage 1: expect it to stop at the first step.
- Force a scan failure (e.g. reply "keep everything exactly as it is, including the customer emails"
  on python-support-triage): expect fix attempts, then either a pass or a "not produced" comment with a
  masked report, and no zip.
- Set `agent = "claude-fable-5-1"` in `config.toml` and repeat one Stage 1 run to check the model switch.
